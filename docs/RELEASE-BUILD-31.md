# Build 31 — cinematic client candidate

Serv tested Build 30 at 0.05× and reported severe stutter with `dolly_slow_clock 1`, while `dolly_slow_clock 0` appeared smooth. Build 31 removes the experimental slow camera clock and its command. Dolly playback always uses the engine's own clock, matching Build 30 with that option off.

The shareable Release build keeps demos, dolly, camera roll, recording, CineBot for private/custom matches, and the requested `unlockall` command/configuration. Its menu no longer offers Host, Servers, Players/kick, Developer mode, or legacy bot-lobby controls. It does not initialize the mod's host/matchmaking controls, online server browser, gameplay aim/nameplate tools, or legacy lobby bots. It does not register other mod developer and gameplay commands, including `fh_*`, `god`, `noclip`, and `names_thruwalls`. An existing saved developer-mode setting is ignored. Developer builds retain investigation tools for source work.

The base mod still injects into and patches the game to provide demo/camera features. This candidate has **not** been certified for online play or anti-cheat compatibility. Use it for demos and private cinematic sessions. CineBot remains restricted to its supported WWII executable and private/custom match workflow.

Build 30's capture timing log showed 52–56 source callbacks per second on four 60 FPS ProRes 4444 recordings. Two filled the 8-frame encoder queue and dropped frames; two later recordings had no queue waits or drops but still arrived below 60 callbacks per second. The recorder currently stamps each captured frame at a fixed 60 FPS rather than preserving source presentation times, so export timing can still differ from live playback. Build 31 does not claim to solve that separate capture limitation.
